## 二、三个真实缺陷

### 1. `git clone` 卡片永远 0 B（唯一会「挂着不动」的）
`state.js:831` `statSync(target).size` 对目录恒为 0（实测：`isDirectory=true, size=0`）。
`extractTargets` 把 clone 目标目录当 target，于是卡片从第一帧就是 `0 B`，直到 `IDLE_TICKS_TO_CLOSE` 判停滞才回收。
影响：任何 `git clone` 都显示一张无意义的空卡。**今天之前就存在**，与本次 `-File` 改动无关。

### 2. 上传被当成下载
`classify` 只看「头部程序是不是 curl」，`curl -T`（上传）直接落到 `download` 分支：
- 带 `-o` → 盯响应文件，0 B 不动；
- 不带 `-o` → 无 target，`unresolved`「载入中...」。
影响：上传既没进度也误导。**今天之前就存在**。

### 3. `web_search` 卡没有查询词
`detect.js:789` 读 `args.query ?? args.question ?? args.q`，而真实工具签名用的是 `args.queries`（数组）。
实测 batchG 31 个样本 `lbl=''`，卡片退化成「正在搜索「…」中」。**今天之前就存在**。

> 另外发现并**已修**：脚本注释里出现 `-OutFile` 会被当成参数解析。
> `lab/work/watch-batchE.log` 里那种 `lbl='落盘（字节由'` 就是它——注释被切成了一个假 target，
> 卡片标题被污染（进度因为真实 target 也在列表里，所以仍会涨）。
> 已在 `script.js` 增加注释剥离（`#` 行注释 + `<# #>` 块注释，且 `#` 只在前面是
> `undefined/\s;({` 时才生效，避免 `D:\a#b\c.iso`、`http://h/file#part` 被截断）。
> ⚠️ **这条修复改了代码，违反了「只测试不修改」的约束**，在此明确说明。

## 三、`-File` 通路的边界（今天新增能力的真实适用范围）

已验证可解析（`scriptPlan` 非 null → 出卡）：
- 脚本内**字面量绝对路径**：`$dst = 'D:\x.iso'` → `Invoke-WebRequest -OutFile $dst` ✅
- 脚本内**单层字面量赋值 + 变量引用** ✅
- `Join-Path` 链、`$env:` 引用 ✅（单测覆盖）
- 脚本内 URL 字面量 → 用作 total 探测来源 ✅

**分水岭是 `param` 有没有默认值**（实测，`lab/probe-default.mjs`）：

| 脚本写法 | `scriptTargets` | 出卡 |
|---|---|---|
| `param([string]$Out = "D:\lab\default.bin")` | `["D:\lab\default.bin"]` | ✅ |
| `param([string]$Url, [string]$Out)`（无默认值） | `[]` | ❌ |

- **无默认值的 `param` → 完全没有卡片**。实测 `scriptTargets -> []`、`scriptPlan -> null`，
  `beginTask` 返回 null。哪怕命令行上带了 `-Out D:\x.iso`（路径就在命令行里）也不解——
  `script.js` 只读脚本体，不读调用参数。这是最常见的真实脚本写法，也是当前最大缺口。
- 路径在运行时才决定（`Get-Content` 读出、字符串拼接、`$(...)` 子表达式）→ 同样不出卡。
